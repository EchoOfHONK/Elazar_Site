# AYROHANT Dark Fantasy Manga Site

## Debian: установка одной командой

На Debian 12/13 (amd64 или arm64), в SSH-терминале от **root**:

```bash
curl -fsSL https://raw.githubusercontent.com/EchoOfHONK/Elazar_Site/main/install.sh -o install-elazar.sh && bash install-elazar.sh
```

Если `curl` ещё нет: `apt-get update && apt-get install -y curl`.
Установщик скачает сайт в `/opt/elazar`, установит Docker и Compose, создаст
отдельный пароль админки и запустит контейнер. Он найдёт существующий Nginx
Proxy Manager и подключится к его обычной Docker-сети. Если NPM нет, он
создаст новую установку с SQLite и попросит email первого администратора.

Введите домен сайта и данные администратора существующего NPM; пароль
вводится скрыто. Скрипт создаст Proxy Host, выпустит сертификат Let’s Encrypt
и включит HTTPS. При двухфакторной авторизации NPM он попросит код. До
запуска домен должен указывать A-записью на сервер, а порты 80/443 должны
быть доступны извне. Скрипт не управляет DNS у регистратора. При ошибке
выпуска сертификата HTTP-хост останется доступен; исправьте DNS и повторите
запуск. Настройки чужого Proxy Host для занятого домена не перезаписываются.
Для автоматизации используется официальный API NPM; новый NPM закреплён
на версии 2.16.0. Старые версии и нестандартные образы могут потребовать
настройки Proxy Host вручную: `http` → `elazar-site` → `3000`.

Можно оставить домен пустым и посмотреть сайт через SSH-туннель:

```bash
ssh -N -L 3300:127.0.0.1:3000 USER@SERVER_IP
```

Затем откройте `http://127.0.0.1:3300`. Сайт не открывает порт 3000 в интернет.
Админка сайта — `/admin.html`; логин и пароль скрипт выведет в конце и
сохранит в `/opt/elazar/.env`. Для новой установки NPM он также выведет её
email и отдельный пароль из `/opt/elazar/npm/.env`. Панель нового NPM
привязана к `127.0.0.1:81`; для входа используйте туннель
`ssh -N -L 8181:127.0.0.1:81 USER@SERVER_IP` и `http://127.0.0.1:8181`.

Обновление выполняется тем же установщиком:

```bash
sudo bash /opt/elazar/install.sh
```

Контент и загруженные файлы сохраняются в именованных томах `elazar_data`
и `elazar_uploads`; обновление исходников их не заменяет. Скрипт сохраняет
пароли, домен и порт проверки. Не используйте `docker compose down -v`:
эта команда удаляет тома. Если в Git-каталоге есть ручные правки, установщик
остановится до обновления и оставит их на месте. Для ручного управления
контейнером используйте `cd /opt/elazar` и
`docker compose --env-file .deploy.env ps` (или `logs`, `up -d`, `stop`).
Установка рассчитана на один экземпляр сайта и NPM на том же сервере.

Параметры для нестандартной установки:

```bash
bash /opt/elazar/install.sh --domain sketchbook.example.com --npm-container npm-app-1
bash /opt/elazar/install.sh --dir /opt/my-elazar --network npm_default --preview-port 3301
```

Существующие тома NPM, его другие сайты, Docker-пакеты и сеть сохраняются.
При конфликтующих пакетах или отсутствующей у NPM обычной bridge-сети
скрипт покажет причину остановки. Сеть задаётся в Compose сайта постоянно;
временное подключение `docker network connect` не используется.

Основа установки: [официальная инструкция Docker для Debian](https://docs.docker.com/engine/install/debian/),
[общая Docker-сеть NPM](https://nginxproxymanager.com/advanced-config/#best-practice-use-a-docker-network)
и [API NPM](https://github.com/NginxProxyManager/nginx-proxy-manager/tree/v2.16.0/backend/schema).

Проверка установщика для разработчиков (Python 3, Bash и Node.js):
`python3 deploy/test-installer.py`. Команды Docker, Git и APT заменяются
изолированными заглушками; тесты не устанавливают пакеты и не запускают
контейнеры. API-проверки используют контрактные ответы NPM.

## Главная страница: 4 октября 2026

Главная — сетка из семи карточек, которая помещается в высоту окна без прокрутки страницы, включая телефон и горизонтальный экран. Карта, баллады, сказания и некрономикон открываются на своих страницах; полные хроники и соцсети с Twitch открываются в диалоге с внутренней прокруткой. Прямые ссылки `/#chronicles` и `/#sources` сохранены. Twitch загружается при открытии диалога и останавливается при закрытии.

Оформление главной находится в `public/home.css`, логика карточек и диалогов — в `public/home.js`. Данные по-прежнему читаются из `data/content.json` и редактируются в существующей админке. Три фэнтезийных фона `public/assets/themes/fantasy-*.png` переключаются вместе с темой, без цветовых фильтров и растяжения. Пустое поле фона в админке включает фоны тем; свой фон применяется ко всем темам.

В админке появился раздел **«Главная»**. Он управляет приветствием, большой карточкой мира, шестью карточками разделов, их ссылками, значками, обложками, подписями и счётчиками. Изображения для трёх тем и их положение задаются отдельно; загрузка сохраняет исходные пропорции. Тексты окон и тихий задний фон (линии атласа, бумажная фактура или без фактуры) тоже доступны здесь. Настройки сохраняются в `home`; `public/home-settings.js` содержит общие значения по умолчанию для сайта и админки, поэтому прежние файлы контента продолжают работать.

Хроники оформлены как доска объявлений: листочки на главной берут заголовки двух последних видимых новостей. Социальные значки — отдельные ссылки, которые используют адреса из раздела **«Соцсети»**. Их порядок задаётся списком ID в настройках главной; портреты аналогично берутся из раздела **«Персонажи»**. Оставьте подпись счётчика пустой для автоматического подсчёта или задайте свой текст; флажок позволяет скрыть её.

## Быстрый запуск

Нужен Node.js 18+.

Windows PowerShell:

```powershell
cd "C:\Users\Surface Pro 7\Documents\ALL-SYSTEM\dark-fantasy-manga-site"
Copy-Item .env.example .env
# Откройте .env и задайте уникальные ADMIN_LOGIN и ADMIN_TOKEN.
node .\server.js
```

Linux/macOS:

```bash
cd dark-fantasy-manga-site
cp .env.example .env
# Откройте .env и задайте уникальные ADMIN_LOGIN и ADMIN_TOKEN.
node server.js
```

После запуска:

- сайт: `http://localhost:3000`
- читалка: `http://localhost:3000/reader.html`
- баллады: `http://localhost:3000/ballads.html`
- сказания: `http://localhost:3000/legends.html`
- некрономикон: `http://localhost:3000/wiki.html`
- карта: `http://localhost:3000/map.html`
- админка: `http://localhost:3000/admin.html`

## Доступ в админку

Логин и пароль задаются в локальном файле `.env`, который не попадает в Git. Скопируйте `.env.example` в `.env` и замените демонстрационные значения на свои. Переменные окружения системы имеют приоритет над файлом `.env`:

```powershell
$env:ADMIN_LOGIN="your-login"
$env:ADMIN_TOKEN="your-strong-password"
```

или:

```bash
ADMIN_LOGIN="your-login" ADMIN_TOKEN="your-strong-password" node server.js
```

## Как пользоваться админкой

1. Откройте `http://localhost:3000/admin.html`.
2. Введите логин и пароль.
3. Выберите раздел слева.
4. Отредактируйте нужный контент.
5. Нажмите `Сохранить всё`.

Разделы админки:

- `Основное` - название сайта, герой-блок, подвал.
- `Twitch` - ник канала для встроенного блока.
- `Новости` - карточки на главной.
- `Манга` - тома, главы, страницы и изображения страниц.
- `Баллады` - плейлисты, solo-треки, обложки, фоны, аудиофайлы и тексты.
- `Некрономикон: персонажи` - имя, роль, фракция, описание, аватарка.
- `Некрономикон: локации` - название, тип, описание, изображение и пины карты.
- `Соцсети` - внешние ссылки.

## Рекомендуемые размеры изображений

Эти размеры продублированы в админке над соответствующими блоками.

| Что загружаете | Размер | Формат | Где используется |
| --- | --- | --- | --- |
| Портрет персонажа | `900 x 1200 px` | вертикальный `3:4` | карточки персонажей и просмотр оригинала |
| Изображение локации | `640 x 640 px` | квадрат `1:1` | карточки локаций, панель карты, просмотр оригинала |
| Фон карты | `2400 x 1600 px` или больше | горизонтальный `3:2` | публичная карта и редактор пинов |
| Обложка плейлиста / трека | `1000 x 1000 px` | квадрат `1:1` | карусель баллад, список треков, нижний плеер |
| Фон плейлиста | `2400 x 1400 px` или больше | горизонтальный `12:7` | задний фон страницы баллад при выборе плейлиста |
| Страница манги | любой единый размер для главы | вертикальный или разворот | читалка манги |

Для портретов лучше держать лицо и силуэт ближе к центру. Для карты оставляйте важные места не у самого края, чтобы пины и масштабирование не выглядели тесно.

## Манга и читалка

Структура манги:

```text
Том -> Глава -> Страница
```

Для страниц можно:

- загрузить изображение через админку;
- указать URL картинки вручную;
- менять порядок страниц кнопками `Выше` / `Ниже`;
- оставить текстовый placeholder, если картинки пока нет.

Загруженные через админку файлы сохраняются в:

```text
public/assets/uploads/
```

## Некрономикон

Некрономикон живёт на:

```text
/wiki.html
```

Там два раздела:

- персонажи;
- локации.

Аватарки и изображения кликабельны: при клике открывается оригинал в крупном просмотре.

## Карта

Карта вынесена отдельно:

```text
/map.html
```

На публичной карте:

- пины кликабельны;
- справа показывается выбранная локация;
- ползунок меняет масштаб карты.

В админке карта редактируется в разделе `Некрономикон: локации`:

- фон карты загружается в поле `Загрузить фон карты`;
- двойной клик по карте добавляет новый пин;
- перетаскивание пина меняет координаты `X` и `Y`;
- список справа быстро выбирает нужную точку;
- удалить пин можно удалением соответствующей локации;
- точные координаты можно править руками в полях `X на карте, %` и `Y на карте, %`.

## Баллады

Баллады живут на отдельной странице:

```text
/ballads.html
```

На странице есть:

- карусель плейлистов со стрелками влево и вправо;
- отдельный фон у каждого плейлиста;
- автоматическая смена заднего фона страницы при выборе плейлиста;
- список треков внутри выбранного плейлиста;
- нижний аудиоплеер;
- боковая панель с текстом плейлиста или выбранного трека.

Solo-трек лучше заводить как обычный плейлист с одним треком и типом `solo`. Так он будет выглядеть и управляться так же, как остальные баллады.

В админке раздел `Баллады` позволяет:

- добавлять и удалять плейлисты;
- менять порядок плейлистов;
- загружать обложку плейлиста;
- загружать фон плейлиста;
- задавать акцентный цвет плейлиста;
- добавлять и удалять треки;
- менять порядок треков;
- загружать аудиофайл трека;
- загружать отдельную обложку трека;
- редактировать текст для боковой панели.

Поддерживаемые аудиоформаты:

```text
.mp3, .wav, .ogg, .m4a
```

Максимальный размер одного загружаемого файла сейчас `350 MB`. Если трек пока не загружен, кнопка воспроизведения откроет боковую панель с текстом, но аудио не запустится.

## Хроники и сказания

В `Новости` каждая карточка может содержать текст, ссылку и медиа: картинку или локальное видео. В админке укажите `Тип медиа` (`image` или `video`) и загрузите файл в поле «Загрузить картинку или видео». Для роликов используются `.mp4` и `.webm`.

`/legends.html` - видеораздел «Сказания». В админке он состоит из трёх уровней:

```text
Сказание -> Эпизод -> Главы и варианты качества
```

Для эпизода можно загрузить основной `.mp4`/`.webm`, добавить несколько вариантов качества (например, `720p` и `1080p`) и разметить главы. Начало каждой главы задаётся числом в секундах: `90` соответствует `1:30`. Плеер поддерживает запуск кнопкой или пробелом, звук, скорость, качество, переходы по главам, широкий и полноэкранный режимы. Сервер отдаёт видео с byte range-запросами, поэтому перемотка работает и для локальных файлов.

Рекомендуемые материалы для сказаний:

| Что загружаете | Рекомендуемый размер | Формат |
| --- | --- | --- |
| Обложка сказания | `1600 x 900 px` | `16:9`, jpg/png/webp |
| Видео эпизода | `1920 x 1080 px` | `.mp4` H.264/AAC или `.webm` |

```bash
pm2 startup
```

Для домена обычно ставят Nginx перед Node.js и проксируют запросы на `http://127.0.0.1:3000`.

Пример Nginx:

```nginx
server {
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## Безопасность

- Не публикуйте файл `.env` и настоящие `ADMIN_LOGIN` и `ADMIN_TOKEN` в открытом репозитории.
- Для публичного сервера обязательно задайте свои значения переменных окружения.
- Делайте резервные копии `data/content.json`.
- Папку `public/assets/uploads/` тоже стоит бэкапить, потому что там лежат изображения, загруженные через админку.
